# T480 USB-C negotiated voltage

Firmware-gated support for **ThinkPad T480 / N24HT37W**, tested on coreboot.

```nix
hardware.thinkpadEc.pdContract = true;
```

Or load `thinkpad_ec_hwmon` with `pd_contract=1`. This adds two channels:

```text
USB-C PD0 negotiated: 20.00 V
USB-C PD1 negotiated:     N/A
```

Physical mapping verified by moving the charger on the tested T480:

- PD0: lower USB-C port, with Thunderbolt support.
- PD1: upper USB-C port, without Thunderbolt.

The value is the **negotiated fixed-PDO voltage**, not a measured VBUS ADC
voltage. Disconnected ports, ports sourcing power, Type-C-only charging, and
unsupported variable/battery/PPS PDO formats return unavailable. These
channels remain visible so reconnecting a charger does not require reloading
the driver. Linux caches each snapshot for one second; EC cache update latency
is separate and has not been characterized.

## Evidence

Schematic sheet 33 identifies U207, SN1701012 / TPS65988-family PD controller,
with its I2C1 bus routed to the EC. Linux on the tested coreboot installation
exposes only AC online status, without a Type-C/PD power-supply device.

N24HT37W has two controller-cache records at **0x80368c**, stride **0x90**.
Response handler near **0x2a932**, case **0x34**, copies six bytes into record
**+0x1f**. This agrees with TI's
[Active Contract PDO register 0x34](https://www.ti.com/lit/ug/slvubh2b/slvubh2b.pdf),
whose first four payload bytes contain the selected PDO. Firmware getter
**0x2a284** independently decodes the same voltage/current fields.

The driver reads only four aligned words per record, twice:

| Offset | Meaning used by this driver |
| --- | --- |
| +0x00 | Record initialized/enabled, bit 1 |
| +0x14 | EC-transformed Power Status: present bit 6, sink bit 5, PD charging mode bits 4:3 = 3 |
| +0x1c | Contains first PDO byte in bits 31:24 |
| +0x20 | Contains remaining PDO bytes in bits 23:0 |

The reconstructed fixed PDO uses bits 19:10 in 50 mV units. Values outside
5–20 V, zero current capacity, and non-fixed supply types are rejected.
Copies must agree before decoding. A disconnected cache cannot publish an old
PDO simply because its data bytes remain in memory.

Initial upper-port capture: status **0x78**, PDO **0x00064145**, decoding to
**20,000 mV**, source capability **3,250 mA**. The latter is a capability ceiling,
not measured current or proof of the RDO's requested operating current, and
is not exposed as a current sensor. Moving the charger to the lower port
changed PD0 to 20 V and PD1 to unavailable.

## Access, safeguards, and validation

Uses fixed-address EC debug reads, shared with the optional cell-group path.
It can enable the firmware's volatile slot-1 debug permission, using the same
public N24HT37W key documented in [cell-group access](t480-cells.md).
This permission remains enabled after unloading. No PD controller command,
contract renegotiation, charger policy, target RAM, or firmware write is used.
All requests hold ECLK; request shadows are restored unless a timeout could
leave a command in flight. Errors never return a previous successful voltage.

PD support is a separate capability and opt-in, independent of `cellVoltages`.
X230 and unverified profiles cannot expose these channels.

Validation: actual C decoder/transaction tests cover fixed 5/9/15/20 V PDOs,
malformed and unsupported formats, disconnected/source/Type-C-only states,
torn copies, caching and stale-data rejection, denied access, timeout/busy/
restoration errors, and visibility gates. The installed module built against
Linux 7.3.0; both ports were verified live, while battery/temperature telemetry
and accelerometer rotation continued working. NixOS configuration was activated.
Lower-voltage chargers, simultaneous dual inputs, reboot and suspend/resume
have not been physically tested.
